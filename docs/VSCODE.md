# Писать программы в VS Code

В VS Code писать программы удобнее, чем в редакторе игры: подсветка, подсказки функций API,
документация при наведении, ошибки ещё до публикации. Сохранили файл — программа опубликована в игре.

## Один раз

1. Установите [Node.js](https://nodejs.org) 18 или новее (нужен утилите синхронизации).
2. Параметр запуска игры: `--enable-lua-udp 27155`. В Steam: Factorio → Свойства → Параметры запуска.
   По нему мод получает программы из VS Code (и в одиночной игре, и в игре по сети).
3. В игре: окно машины → «Программы…» → **«Папка для VS Code»**. Мод запишет в папку данных игры
   `script-output/automaton/<команда>/` всё нужное:
   - программы команды (`Шахтёр.ts` и т. д.),
   - `automaton.d.ts` — типы API, `tsconfig.json`,
   - `automaton-sync.mjs` — утилита синхронизации,
   - `.vscode/tasks.json` — задача, которая запускает утилиту при открытии папки.

   Папка данных игры: Windows — `%APPDATA%\Factorio`, macOS — `~/Library/Application Support/factorio`,
   Linux — `~/.factorio`.
4. Откройте эту папку в VS Code (Файл → Открыть папку) и разрешите автоматическую задачу
   «Automaton: публиковать при сохранении».

## Каждый день

- Сохранили файл `.ts` — программа опубликована в игре, машины с ней перезапущены. Имя программы —
  имя файла (или первая строка `// @program Имя`).
- Ошибки, которые нашла игра, подчёркнуты прямо в коде (как ошибки TypeScript).
- Программы, которые товарищи опубликовали в игре: `node automaton-sync.mjs pull` в терминале VS Code.
- В одной папке может быть сколько угодно программ: каждый файл — отдельная программа (одинаковые
  имена в разных файлах друг другу не мешают — `moduleDetection: "force"` в `tsconfig.json`).

## Выделенный сервер

На выделенном сервере (`--start-server`) UDP не работает (Factorio 2.0.77 падает), там — RCON:
сервер запускается с `--rcon-port 27015 --rcon-password …`, а утилита —
`node automaton-sync.mjs watch . --rcon --port 27015 --password …` (пароль можно положить в
переменную `AUTOMATON_RCON_PASSWORD` или в `.automaton-sync.json`: `{ "rcon": true, "port": 27015, "password": "…" }`).

## Что знать

- Если в игре есть ошибки, которых не видел VS Code, — это возможности TypeScript, которых нет в языке
  машин (список — [LANGUAGE.md](LANGUAGE.md), «Не поддерживается»): `var`, `async`, регулярные выражения,
  `enum` и т. п. Текст ошибки подскажет, что заменить.
- Игра тоже проверяет типы при публикации, но мягче VS Code: только то, где ошибка несомненна (нет
  такого свойства, не тот аргумент, не то число аргументов). «Возможно null» игра не проверяет — это
  подскажет VS Code.
- `null` и `undefined` в языке машин — одно и то же, `==` запрещено: пишите `===`.
- Действия (`move`, `mine`, `put`…) просто ждут окончания — без `async`/`await`.
- Справка по API — [API.md](API.md), по языку — [LANGUAGE.md](LANGUAGE.md).
