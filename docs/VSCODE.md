# Писать программы в VS Code

**English:** [en/VSCODE.md](en/VSCODE.md)

В VS Code писать программы удобнее, чем в редакторе игры: подсветка, подсказки функций API,
документация при наведении, ошибки ещё до публикации. Сохранили файл — программа опубликована в игре.

## Один раз

1. Установите [Node.js](https://nodejs.org) 18 или новее (нужен утилите синхронизации; в Linux для
   программ в подпапках — 20 или новее).
2. Параметр запуска игры: `--enable-lua-udp 27155`. В Steam: Factorio → Свойства → Параметры запуска.
   По нему мод получает программы из VS Code (и в одиночной игре, и в игре по сети).
3. В игре: окно машины → «Программы…» → **«Папка для VS Code»**. Мод запишет в папку данных игры
   `script-output/automaton/<карта>/<команда>/` всё нужное (у каждой карты — своя папка, имя карты —
   `карта-<номер карты>`):
   - программы команды — в папке `src` (`src/Шахтёр.ts`, `src/lib/Помощники.ts` и т. д.),
   - `automaton.d.ts` — типы API, `tsconfig.json`,
   - `automaton-sync.mjs` — утилита синхронизации,
   - `.vscode/tasks.json` — задача, которая запускает утилиту при открытии папки,
   - `.automaton-map.json` — какой карты эта папка,
   - плагин TypeScript (`.automaton/`) и `.vscode/settings.json`, который его подключает.

   Папка данных игры: Windows — `%APPDATA%\Factorio`, macOS — `~/Library/Application Support/factorio`,
   Linux — `~/.factorio`.
4. Откройте эту папку в VS Code (Файл → Открыть папку) и разрешите автоматическую задачу
   «Automaton: публиковать при сохранении».

## Каждый день

- **Папка `src` — зеркало программ команды в обе стороны.** Сохранили файл — программа опубликована,
  машины с ней перезапущены; удалили файл — программа удалена в игре; переименовали или перенесли файл —
  программа переименована (импорты в других программах поправятся). И обратно: опубликовали, удалили
  или переименовали программу в игре (или это сделал товарищ) — файлы в `src` меняются так же.
  Имя программы — путь файла в `src` без `.ts`: `src/lib/Помощники.ts` — программа `lib/Помощники`
  (или первая строка `// @program Имя`).
- **Модули:** программы импортируют друг друга как обычные файлы TypeScript —
  `import { nearMarker } from "../lib/Помощники"` (подробно — [LANGUAGE.md](LANGUAGE.md), «Модули»).
  Подсказки, переход к определению и переименование с правкой импортов работают как в любом проекте.
- Сохранили библиотеку — в игре пересобираются программы, которые её импортируют. Если какая-то
  из них с новой версией не собралась, её ошибки появятся в её файле (в игре она работает на прежней сборке).
- Ошибки, которые нашла игра, подчёркнуты прямо в коде (как ошибки TypeScript).
- Программы, которые товарищи опубликовали в игре: `node automaton-sync.mjs pull` в терминале VS Code.
- В одной папке может быть сколько угодно программ: каждый файл — отдельная программа (одинаковые
  имена в разных файлах друг другу не мешают — `moduleDetection: "force"` в `tsconfig.json`).
- **Папка — одной карты.** Если в игре открыта другая карта, утилита ничего не публикует и пишет
  «эта папка — для карты …, а в игре открыта …»: откройте папку этой карты («Папка для VS Code» в ней).
- **Подсказки и ошибки плагина** (только для файлов в `src` этой папки): то, чего нет в языке машин
  (`async`/`await`, `var`, `enum`, регулярные выражения, `==` …), подчёркнуто ошибкой ещё до публикации.
  Наведите на `for` / `while` — цена витка и сколько тиков займёт цикл (если число витков видно из кода);
  у таких циклов — подсказка «…». На `publish`, `sort`, `map`, `JSON.parse` — их цена. Если плагин не
  заработал сразу — «TypeScript: Restart TS Server» в палитре команд (Cmd/Ctrl+Shift+P); VS Code должен
  доверять папке.
- **«Обновить из папки»** в окне программ — если меняли файлы, пока задача синхронизации не работала:
  утилита опубликует новые и изменённые файлы, а программы игры без файлов игра покажет и спросит,
  удалить ли их. При запуске утилита сама пишет, чем `src` отличается от игры.
- Утилита обновляется сама: «Папка для VS Code» записала новую версию — задача перезапускается.
  Утилита другой версии, чем мод, получает отказ с подсказкой, что сделать.
- Используемую библиотеку удалить нельзя ни в игре, ни файлом: файл пропадёт, а в игре она останется,
  и в программах, которые её импортируют, появится ошибка «импортирует …, файл которой удалён».
- Если у вас папка старого вида (программы прямо в ней, без `src`) — нажмите «Папка для VS Code» ещё раз:
  программы появятся в `src`; старые файлы программ в корне папки можно удалить, утилита их больше не смотрит.

## Выделенный сервер

На выделенном сервере (`--start-server`) UDP не работает (Factorio 2.0.77 падает), там — RCON:
сервер запускается с `--rcon-port 27015 --rcon-password …`, а утилита —
`node automaton-sync.mjs watch . --rcon --port 27015 --password …` (пароль можно положить в
переменную `AUTOMATON_RCON_PASSWORD` или в `.automaton-sync.json`: `{ "rcon": true, "port": 27015, "password": "…" }`).

## Что знать

- Если в игре есть ошибки, которых не видел VS Code, — это возможности TypeScript, которых нет в языке
  машин (список — [LANGUAGE.md](LANGUAGE.md), «Не поддерживается»): `var`, `async`, регулярные выражения,
  `enum` и т. п. Текст ошибки подскажет, что заменить.
- Игра тоже проверяет типы при публикации, но мягче VS Code: только то, где ошибка несомненна (нет
  такого свойства, не тот аргумент, не то число аргументов). «Возможно null» игра не проверяет — это
  подскажет VS Code.
- `null` и `undefined` в языке машин — одно и то же, `==` запрещено: пишите `===`.
- Действия (`move`, `mine`, `put`…) просто ждут окончания — без `async`/`await`.
- Справка по API — [API.md](API.md), по языку — [LANGUAGE.md](LANGUAGE.md).
