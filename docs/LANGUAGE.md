# Язык программ автоматонов

Строгое подмножество TypeScript: каждая программа — валидный TypeScript (её можно писать в VS Code
с `automaton.d.ts`), но не каждая программа на TypeScript поддерживается. Неподдерживаемое — ошибка
компиляции с понятным текстом и номером строки. Встроенная библиотека — [API.md](API.md),
архитектура компилятора — [DESIGN.md](DESIGN.md), раздел «Архитектура исполнения».

## Что поддерживается (версия 1)

**Значения:** `number`, `string`, `boolean`, `null` / `undefined`, массивы, объекты, `Map`, `Set`,
функции и замыкания, экземпляры классов, ссылки на объекты игры (здания, машины).

**Объявления:** `let`, `const` (блочная видимость), `function`, стрелочные функции, `class`
(поля, конструктор с `readonly`-параметрами, методы, геттеры, `static`, `extends` / `super`, `abstract`,
`implements`), `interface`, `type` (участвуют в проверке типов — ниже).

**Инструкции:** `if` / `else`, `while`, `do … while`, `for (;;)`, `for … of` (массивы, строки, `Map`, `Set`),
`break` / `continue` (в том числе с метками), `return`, `switch` (с проваливанием), `throw`,
`try` / `catch` / `finally`, блоки.

**Выражения:** арифметика (`+ - * / % **`), сравнения (`=== !== < <= > >=`), логика (`&& || !`, с
результатом-операндом, как в JS), `??`, `?.`, тернарный оператор, присваивания (`= += -= *= /= %= **= ??= ||= &&=`),
`++` / `--`, `typeof`, `instanceof`, `in`, шаблонные строки, литералы массивов и объектов (с `...`),
деструктуризация (в объявлениях и параметрах), параметры по умолчанию и `...rest`, вызовы с `...`,
`new`, `this`, `super`, приведение типов `as` и `!` (без эффекта).

**Модули:** `import` / `export` между программами команды — раздел «Модули».

## Представление в Lua

| TypeScript | Lua |
|---|---|
| `number`, `boolean` | число, логическое |
| `string` | строка Lua (UTF-8); `length` и индексы — в символах, а не байтах |
| `null`, `undefined` | `nil` — **одно и то же** (см. «Отличия») |
| массив | таблица `{__a = true, n = длина, [1..n] = элементы}` — с длиной, поэтому `null` внутри не ломает массив |
| объект | таблица со строковыми ключами |
| экземпляр класса | таблица полей + `__cls = класс`; класс — таблица `{__m = методы, __g = геттеры, __s = родитель}` |
| функция, замыкание | данные `{__f = номер функции, __e = окружение}` |
| `Map`, `Set` | таблицы с упорядоченными ключами (порядок вставки) |
| здание, машина | объект игры (`LuaEntity`) |

Ни одно значение языка не содержит функций Lua и метатаблиц, поэтому всё состояние программы —
переменные, кадры остановленных функций, объекты — хранится в `storage` и переживает сохранение.
Скомпилированный код — кэш, который собирается из текста программы при загрузке.

Частые операции (вызовы, чтение полей и индексов, `+`) — функции пролога, который компилятор
вставляет в начало каждой программы (`src/lang/prologue.ts`); остальное — рантайм `src/lang/runtime/`.
Переменная, которую захватывает вложенная функция, кладётся в её окружение значением, если после
объявления не меняется; иначе живёт в ячейке `{значение}`, общей для всех замыканий.

## Функции: короткие и возобновляемые

- **Короткая** — без циклов, без рекурсии, без вызова действий, вызывает только короткие:
  обычная функция Lua, полная скорость. Так компилируется большинство лямбд (`f => f.count(ore) < 10`).
- **Возобновляемая** — все остальные: плоский код на `goto`, точки остановки на витках циклов, входах в
  функции и вызовах действий. Пауза (действие, кончился квант времени) складывает переменные в кадр;
  продолжение восстанавливает их и прыгает в нужное место.
- Замыкание, вызываемое через значение (например, лямбда в `filter`), вызывается через рантайм; если оно
  возобновляемое — используется возобновляемая версия метода массива.

## Отличия от JavaScript

1. **`null === undefined`** — истина: оба — `nil`. `typeof null` — `"undefined"`.
2. **`==` и `!=` запрещены** — только `===` и `!==`.
3. **Числа** — числа двойной точности, как в JS; деление на ноль даёт бесконечность, запись чисел в
   строку — как в JS (`0.1 + 0.2` → `0.30000000000000004`, `1e21`, `1e-7`).
4. **Арифметика и сравнение с `undefined`, объектами, разными типами — ошибка `TypeError`**, а не `NaN`
   и не `false`: `undefined * 2`, `null + 1`, `1 < "2"`. Так ошибку видно сразу. Сложение со строкой —
   склейка, как в JS (`"n:" + null` → `"n:undefined"`).
5. **`for (let i …)` с замыканиями**: каждая итерация получает свою переменную, как в JS.
6. **Порядок ключей объектов** (`Object.keys`, `JSON.stringify`, спред) — по алфавиту, а не порядок
   вставки (одинаково у всех игроков). У `Map` и `Set` — порядок вставки.
7. **`Map.keys()`, `values()`, `entries()`** возвращают массивы, а не итераторы.
8. **Строки** — UTF-8; длина и индексы — в символах (`"дом".length === 3`). `toUpperCase` /
   `toLowerCase` меняют латиницу и кириллицу.
9. **Нет `undefined` в массиве как «дырки»**: `[1, , 3]` — ошибка; `[1, null, 3]` — можно.
10. **Свойства у массивов, `Map`, функций** (кроме `length`) записывать нельзя — `TypeError`.

## Модули

Программа может импортировать другие программы своей команды — свои библиотеки функций, классов и типов.
Путь — относительный, от папки программы, без расширения: программа `Логистика/Перевозчик` пишет
`import { nearMarker } from "../lib/Помощники"` (в VS Code это тот же путь к соседнему файлу).

```ts
// lib/Помощники
export interface Route { item: Item; keep?: number }
export const FUEL: Item = "coal"
export function chestAt(name: string): Entity | null { … }
export default class Depot { … }
```

```ts
// Логистика/Перевозчик
import Depot, { chestAt, type Route } from "../lib/Помощники"
import * as H from "../lib/Помощники"
const chest = H.chestAt("склад")
```

- **Импорт:** `import { a, b as c }`, `import x` (default), `import * as ns` (только `ns.имя`, не как
  значение), `import type { T }` и `{ type T }`, `import "./x"` (только исполнить).
- **Экспорт:** `export` перед `function`, `class`, `const` / `let`, `interface`, `type`; `export { a, b as c }`;
  `export default` (функция, класс или выражение); реэкспорт `export { a } from "./x"`, `export * from "./x"`.
- **Исполнение — как у ES-модулей:** каждый модуль выполняется один раз у каждой машины, до модуля,
  который его импортирует, в порядке зависимостей. Переменные модуля — свои у каждой машины.
  Импортированные имена живые (видят изменения в своём модуле) и только для чтения.
- **Библиотека** — модуль, где на верхнем уровне только объявления и есть `export`. Её нельзя запустить
  на машине: она нужна другим программам.
- **Сборка при публикации:** программа компилируется вместе со всеми модулями в один код. Ошибка
  в модуле показывается с его именем: `lib/Помощники:12:5`, так же — строки ошибок выполнения.
- **Нельзя:** циклический импорт, `import(…)`, `require`, `export =`, `export * as ns`, `import` / `export`
  внутри блока, путь без `./` или `../`. Не больше 50 модулей и 300 000 байт модулей на программу.

## Не поддерживается

`var`, `async` / `await`, генераторы, декораторы, `enum`, `namespace`,
регулярные выражения, `Date`, `Symbol`, `BigInt`, `eval`, `with`, `delete`, `label:` на не-циклах,
геттеры/сеттеры в объектных литералах, сеттеры и статические геттеры в классах, `arguments`,
`prototype`, `Function.call/apply/bind`, `extends` от выражения (только от имени класса или `Error`),
`super` внутри стрелочных функций, идентификаторы и свойства, начинающиеся с `__` (зарезервированы
рантаймом).

## Ошибки

- **Компиляции** — список `{строка, столбец, текст}` по-русски или по-английски (по языку игрока).
- **Выполнения** — исключение; если его не поймали, машина останавливается с ошибкой: текст,
  строка исходника и стек вызовов программы. Ошибки действий — `ActionError` с кодом (API.md).

## Проверка типов

При публикации игра проверяет типы — тем же описанием API, что и `automaton.d.ts` для VS Code
(и описанием встроенной библиотеки). Проверка **постепенная**: ошибка — только там, где она точно есть,
а всё неизвестное (`any`, `JSON.parse`, сложные типы) пропускается без ошибок. Программа, которую
принимает `tsc --strict`, проходит и здесь.

Что проверяется:
- свойства и методы известных типов: `me.cargo.cout(...)` — «у типа Inventory нет свойства cout»;
- число аргументов и их типы: `wait("5")`, `text(…, { align: "middle" })` (нужно `"left" | "center" | "right"`);
- присваивания, начальные значения с аннотацией и `return` по объявленному типу;
- `let x = 1; x = "a"` — тип переменной выводится из значения;
- вызов не-функции, арифметика не над числами (`"x" * 2`).

Выводятся типы переменных, результатов вызовов (в том числе обобщённых: `map`, `reduce`, `find`,
`Map<K, V>`, `receive<T>`), параметров лямбд из контекста (`xs.map(s => s.length)`), классов
и интерфейсов (структурно). Сужение: `=== null` / `!== undefined`, `typeof x === "string"`,
`e instanceof ActionError`, поле-дискриминант (`s.kind === "circle"`), ранний выход
(`if (x === undefined) return`).

Не проверяется (это подскажет VS Code): «возможно `null`/`undefined`», лишние свойства в объектных
литералах, `readonly`, сравнение несовместимых типов.
