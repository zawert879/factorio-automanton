# Automaton — дорожная карта

Задачи выполняются по порядку. Каждая — законченный кусок, который можно проверить.
Перед началом задачи уточняются детали, после — отмечается `[x]` и делается коммит.
Дизайн и решения — в [DESIGN.md](DESIGN.md).

Первая играбельная версия (машина выполняет TS-программу в игре) — конец этапа 4.

---

## Этап 0. Фундамент

- [x] **0.1 Проект на TypeScript.** TypeScriptToLua + typed-factorio 3.x; исходники в `src/`, папка мода `mod/`
  (сюда же собирается Lua), симлинк в папку модов игры переводится на `mod/`; сборка и режим наблюдения;
  демо-код переносится на TS.
  *Готово, когда:* `npm run build` собирает мод, он грузится в игре, демо-команда работает из нового модуля.
- [x] **0.2 Тесты вне игры.** Собрать Lua 5.2 в `tools/` (версия как в Factorio), раннер тестов, которые пишутся
  на TS и собираются в Lua; команда `npm test`.
  *Готово, когда:* пример теста проходит и падает при поломке.
- [x] **0.3 Тесты в игре без окна.** Прогон через `factorio --benchmark` на тестовой карте:
  тесты выполняются в `on_tick` и пишут результат в `script-output`, скрипт разбирает итог.
  *Готово, когда:* `npm run test:game` выдаёт «пройдено/упало» без запуска окна игры.
- [x] **0.4 Проверка десинков.** Инструкция и сценарий проверки: `/toggle-heavy-mode`, сохранение и
  загрузка посреди работы.
  *Готово, когда:* описано в `docs/TESTING.md` и проверено на демо-коде.

## Этап 1. Автоматон ездит (спайк)

- [x] **1.1 Прототип машины.** `unit` на стороне игрока, перекрашенная ванильная графика, предмет и
  временный рецепт; установка через сущность-заглушку.
  *Готово, когда:* машину можно поставить из инвентаря, она стоит и не исчезает.
- [x] **1.2 Реестр машин.** Учёт в `storage` (id, имя, сущность, состояние); смерть, разрушение и подбор
  обратно в инвентарь; id, имя и память сохраняются в предмете (`item-with-tags`); id и имя над машиной.
  *Готово, когда:* после сохранения/загрузки реестр цел, подобранная и снова поставленная машина
  сохраняет id и имя.
- [x] **1.3 Движение.** Поездка к точке или сущности, успех/неудача пути, таймауты; очередь запросов пути
  с бюджетом на тик; отладочная команда `/am-goto`.
  *Готово, когда:* машина объезжает здания и сообщает, если пути нет.
- [x] **1.4 Анимации накладками.** Собственный спрайт юнита прозрачный; бег, простой и добыча — анимации
  rendering по 8 направлениям, переключаемые по состоянию и направлению машины.
  *Готово, когда:* стоящая машина «дышит», едущая бежит в нужную сторону, на сохранение не влияет.
- [x] **1.5 Столкновения и пробки.** Машины сталкиваются друг с другом; обнаружение застревания и пробки,
  разъезд (отступить, переждать, перестроить путь); 200 машин в плотной застройке.
  *Готово, когда:* 200 машин в узком проезде не встают намертво, застрявшие сообщают об этом.
- [x] **1.6 Кэш маршрутов.** *Итог: замерено — свой кэш поверх кэша движка ничего не даёт, остаётся кэш движка.* Повторно используемые маршруты (участки по кэшированному пути), сброс при
  постройке на пути; повтор замера `tools/bench/units` — сравнение с исходными цифрами из DESIGN.md.

## Этап 2. Действия и энергия (через отладочные команды)

- [x] **2.1 Груз и топливо.** Скриптовый инвентарь груза и слот топлива, отладочный вывод содержимого.
- [x] **2.2 Система действий.** Текущее действие машины, обработка по тикам, длительность,
  проверка радиуса досягаемости, отмена.
- [x] **2.3 Добыча.** `mine`: извлечение из месторождения, скорость, истощение, продукты с вероятностью;
  ~~пока машина копает — анимация бура у месторождения~~ — машина сама машет киркой (анимация из 1.4).
- [x] **2.4 Обмен предметами.** `take` / `put` для сундуков, печей, сборщиков, лабораторий, котлов, турелей,
  вагонов — каждый раз в правильный инвентарь.
- [x] **2.5 Предметы на земле и между машинами.** `pickup`, `drop`, `give`, `repair`.
- [x] **2.6 Состояние зданий.** Статус, рецепт, прогресс, содержимое входа/выхода/топлива, жидкости.
- [x] **2.7 Энергия Mk1.** Расход на путь и действия, заправка из груза, остановка без топлива.
- [x] **2.8 Статус над машиной.** Иконка состояния и ошибки, подпись, облачко `say` — через rendering.
  *Готово (весь этап), когда:* отладочными командами можно провести цикл «добыть → отвезти в печь →
  забрать слитки», и машина встаёт без топлива.

- [x] **3.5 Анализ.** Области видимости, захваченные переменные, граф вызовов: какие функции короткие
  (без циклов, рекурсии и действий), а какие возобновляемые.
- [x] **3.6 Генерация Lua: короткие функции.** Выражения, ветвления, классы и наследование, исключения;
  таблица соответствия строк Lua → TS.
- [x] **3.7 Генерация Lua: возобновляемые функции.** Плоский код на `goto`, переменные — локальные Lua,
  в кадр — только при паузе; точки остановки на витках циклов, входах в функции и вызовах действий;

- [x] **3.8 Рантайм-библиотека.** Безопасный доступ к полям и индексам, строки, массивы (обычные и
  возобновляемые версии методов высшего порядка), `Map`, `Set`, `Math`; лимиты памяти и длины строк.
- [x] **3.9 Песочница.** Окружение `load`, белый список; набор тестов-атак: выход из песочницы, методы строк,
  бомбы памяти, бесконечные циклы, глубокая рекурсия, огромная программа.
- [x] **3.10 Тест пауз и сериализации.** Прогон каждого теста с квантами 1…5000 и копированием кадров
  на каждой паузе (как при сохранении) — результат такой же, как без пауз.
- [x] **3.11 Бенчмарк.** Сгенерированный код против обычного Lua в Lua самой Factorio. Цель (по замеру
  прототипа): короткие функции — не хуже 1.2×, возобновляемые — не хуже 1.5×.
  *Итог:* короткие 1.36×, циклы 2.0× — цели не достигнуты (семантика JS и безопасность, см. DESIGN.md,
  «Замер настоящего компилятора»); методы и лямбды 3.5–4× — до проверки типов (этап 12).
  *Готово (весь этап), когда:* примеры из [API.md](API.md) (с заглушками игровых функций) компилируются
  и выполняются в тестах, атаки на песочницу отбиты.

  *Готово, когда:* машина по программе сама добывает руду и кормит печи, переживает сохранение/загрузку.
